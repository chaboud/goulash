# Naming: Candidate Graveyard

Names eliminated by **direct collisions** — an existing shell, terminal
tool, CLI product, or otherwise disqualifying association. Kept as a
record so nobody re-proposes them. Screening method:
[criteria.md](criteria.md).

## The s-l-*-sh phonetic neighborhood (thoroughly strip-mined)

| Name | Killer |
|---|---|
| **slosh** | "Simple Lisp SHell (slosh)" — a Rust-based shell, scripting language, and REPL: the exact category. Great name otherwise (*Small/Session/Streaming LLM Overlay Shell*); might survive as an internal codename, but don't ship the binary. |
| **slash** | `satlab/slash` — embedded command-line editor and shell ("SatLAb SHell"). |
| **slush** | Dallas Semiconductor TINI platform's Unix-like command shell, literally named Slush, 20+ years documented. Plus watery/messy connotation. |
| **slsh** | Executable of the S-Lang shell, packaged by Debian, Cygwin, OpenWrt. Worse: "SLSH" now names the Scattered LAPSUS$ ShinyHunters cybercrime alliance. Hard no. |

Adjacent consonant-heavy names, also mined out: **clsh** (cluster shell +
a Claude-oriented remote terminal), **plsh** (PostgreSQL shell language),
**vlsh** (active Unix shell in V).

## Lessons

The `[letter]lsh` and `[consonant][vowel]sh` patterns are exactly what
shell authors have exhausted for decades. Anything four letters ending in
`sh` should be presumed taken until proven otherwise. This is what pushed
the search toward real words ([goulash, lavash](decision.md)) and
constructed compounds ([CoaSH, FLESH](runner-ups.md)).
