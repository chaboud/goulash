# goulash-bench — engine characterization

Measures three things across local engines and models:

1. **Behavior** — who honors the one-line + `CMD:` contract
2. **Performance** — where the wall clock actually goes
3. **Setting tolerance** — do models need per-model quirks, or does one
   setting matrix cover them

It drives goulash's *real* engine (`build_prompt`, the `Provider` impls,
`split_answer`) via the lib target, so results describe the product and
cannot drift from it.

## Running

```sh
cargo build -p goulash-bench

# tolerance probe first — prunes broken cells cheaply
./target/debug/goulash-bench pass-a bench/results/2026-07-28

# the sweep: 3 shapes x 19 asks x 30 cells
./target/debug/goulash-bench pass-b bench/results/2026-07-28

./target/debug/goulash-bench report bench/results/2026-07-28
./target/debug/goulash-bench blind  bench/results/2026-07-28
./target/debug/goulash-bench grade  bench/results/2026-07-28
./target/debug/goulash-bench replay bench/results/2026-07-28 <key|blind-id>
```

Prefer `bench/run.sh DIR`, which runs both passes and unloads every model
on both engines on any exit path — including SIGTERM. Without that a
killed run strands a multi-GB model resident (LM Studio JIT-loads at a
1-hour TTL).

Narrow the catalog for a smoke test or to rerun one model:

```sh
GOULASH_BENCH_ONLY="qwen3.5:0.8b,gemma4" ./target/debug/goulash-bench pass-b DIR
```

**LM Studio must be up** for its 8 cells: `~/.lmstudio/bin/lms server start`.

## Interrupting and resuming

Safe to kill at any moment. **Rerun the identical command** — completed
cells are skipped and the run continues.

- `journal.jsonl` — one row per completed cell, flushed and fsynced
  before the call returns, so an interrupt cannot lose a finished cell.
  A torn final line from a hard kill is treated as absent and redone.
- `manifest.jsonl` — the full plan, written before any work, so coverage
  is auditable even from a partial run.
- `prompts.jsonl` — full prompt text, split out to keep resume fast.

Resume replays each recorded answer's effect on the session log rather
than skipping it, so prompts stay byte-identical to the original run. It
has to: the sweep's whole point is comparing prompt shapes, and a resumed
session that built slightly different prompts would corrupt that quietly.

The clock is frozen (`NOW` in `main.rs`) for the same reason — `Current
local time:` sits in the volatile suffix, so a live clock would make two
runs of the same cell differ.

## Layout

```
catalog.toml     30 model cells (22 ollama + 8 LM Studio)
scenarios.toml   GENERATED by harvest.py — do not hand-edit
harvest.py       runs safe real commands, captures real output
src/journal.rs   append-only crash-safe results
src/sweep.rs     pass B: scripted sessions, model-major
src/probe.rs     pass A: setting-tolerance probes
src/report.rs    report card, blind corpus, replay
results/step0/   pre-sweep findings that shaped the design
QUIRKS.md        pass-A verdict: which settings need per-model handling
HEADROOM.md      what actually caps a long CMD (not max_tokens)
RESUME.md        current state, and which of my claims to distrust
```

One sweep per results directory: `Journal::open` takes an exclusive lock.
Two concurrent sweeps contend for the GPU and unload each other's models,
which silently corrupts both sets of timings.

## Prompt shapes

| shape | what it varies | question it answers |
|---|---|---|
| S1 | shipped: memories before the log | baseline |
| S2 | memories in the volatile suffix | what does `memory.rs:148`'s prefix invalidation cost? |
| S3 | `CMD:` before the prose line | does command-first help latency, and does it cost quality? |

## Grading protocol

Blind first, then open — so priors about which models are good cannot
reach the scores.

1. `blind` writes `blind.md` (answers only, identity stripped, grouped by
   question, deterministically shuffled) plus `blind_keys.jsonl`.
2. Grade on the text alone into `grades.jsonl`:
   `{"id":"a1b2c3","correct":0-3,"idiom":0-3,"fit":0-3,"why":"..."}`
3. Join back via `blind_keys.jsonl`.
4. A second *open* pass over the same corpus produces the quirks
   narrative that blind grading structurally cannot see.

Everything except the qualitative scores reproduces on a rerun.
`replay <id>` prints the exact prompt and raw response behind any grade,
with no summarization in between.

## Reading the numbers honestly

- **Cache**: ollama reports *total* prompt tokens regardless of cache
  hits, so counts reveal nothing. `prompt_eval_ms` at a fixed token count
  is the direct signal. LM Studio exposes no prompt-eval timing at all —
  its cache evidence is TTFT flatness as the log grows.
- **`contends = true`** cells (13 GB+) cannot fit comfortably in 24 GB.
  Their latency partly measures memory pressure; the report labels them
  rather than presenting them as comparable.
- Pass A eliminations are mechanical (won't load / always empty / never
  parses), never taste.

See `results/step0/FINDINGS.md` and `results/step0/LMSTUDIO.md` for the
measurements that shaped these choices, including two cases where a
probe's own automated verdict was wrong and was corrected against raw
data.
